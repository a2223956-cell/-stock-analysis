## 一、核心原则: 实时数据(不可违反)

**所有行情扫描和分析必须基于实时数据,不依赖文件中的静态数据。**

文件角色(只是"名单",不是"数据源"):
- unified_pool.txt = 扫描范围(股票代码列表,无价格)
- actionable_pool.txt = 候选名单(评分是扫描时的快照,不是当前值)

⚠️ 文件中的价格只是扫描时的快照,实际操作时必须重新拉取实时行情。

---

## 二、7条核心交易理念（不可违反）

1. **严进策略** — 不追高，乖离率(MA5偏离)<5%才考虑入场
2. **趋势交易** — MA5>MA10>MA20多头排列，顺势而为
3. **效率优先** — 关注筹码结构好、资金配合的票
4. **买点偏好** — 优先在MA5/MA10附近回踩买入，不追突破
5. **风险排查** — 高风险利空一票否决，宁错过不做错
6. **量价配合** — 成交量必须验证价格运动，无量上涨=虚假
7. **龙头放宽** — 真正的板块龙头可适当放宽标准，但必须有辨识度

## 三、分析流程概览（9步法）

**⚠️ 执行前置要求: 接到分析任务后，第一步必须告知用户将调用哪些skill。**

### 深度分析流程:
```
步骤-1: 历史分析复盘（深度分析时必做）→ stock-reports目录
步骤1: 前复权处理（必做）
步骤2: 市场环境扫描（大盘+板块）
步骤3: 量价关系分析（核心）
步骤4: 资金流向验证
步骤5: 技术面+均线系统
步骤6: 情绪周期分析
步骤7: 估值+基本面
步骤8: 概念板块完整映射（必做）
步骤9: 消息面+事件驱动+风险筛查
```

### 步骤-1: 历史分析复盘（深度分析时必做）

> 完整版见 stock-analysis-deep（含复盘输出模板与K线数据校验硬规则）

当用户说"深度分析XX"时，在正式分析前先检查历史记录：

1. 搜索历史报告:
   ```bash
   search_files(pattern="*分析报告*", target="files", path="/home/harry/stock-reports/{股票名}_{代码}")
   ```
   + `session_search(query="{股票名} {代码} 分析")`

2. 如果找到历史报告:
   - 读取报告中的操作建议/支撑位/阻力位/主力判断/综合评分
   - 拉取当前数据(腾讯行情)对比价格变化
   - 输出复盘(✅/❌验证 + 遗漏分析)

3. 如果没有历史报告: 跳过，正常执行后续步骤

**关键规则**:
- 复盘结果放在分析报告最前面(在市场环境之前)
- 复盘必须诚实: 上次判断对了就说对了，错了就说错了
- 如果上次的支撑位/阻力位被击穿，本次分析必须重新计算

### 批量分析工作流（2+只票）

1. **告知skill列表** → 告诉用户将调用哪些skill
2. **主agent预取全部数据** → 用terminal/execute_code批量获取K线、资金流、板块
3. **并行委托** → delegate_task, 每只票一个子agent
4. **交叉验证** → 子agent报告中的关键价位做API校验
5. **呈现给用户** → 逐票展示 + 末尾横向对比表

### "还拿不拿"/"该卖吗"/"加仓"类问题

**第一步(不可跳过): 确认成本价** → 用clarify工具问用户
**第二步: 结论先行** → 先给结论再展开分析

## 五、执行前置: 输出格式(不可跳过!)

**PITFALL: 主agent直接写报告时最容易跳过模板!**

深度分析报告必须包含以下章节(按顺序):
1. 核心数据速览 (腾讯API实时行情)
2. 历史复盘 (对比上次报告结论vs实际走势)
3. 市场环境分析 (大盘指数+板块强弱)
4. 量价关系深度分析(K线形态+阶段判断)
5. 资金流向分析(20日逐日资金流)
6. 均线与技术面分析(MA5/10/20/30)
7. 估值与基本面分析(PE/PB+概念板块)
8. 综合评分与操作建议(5维度加权)
9. 风险提示(5-6条)
10. 附录: 完整K线数据
